# Asanchez

Автономный сервис, который следит за задачами в Asana (Prestige Expo) по
регламенту из «Asanchez: Инструкция по задачам Asana»:

- проверяет формат названия задач (`[KOD] — [Verbo infinitivo] + complemento`,
  протоколы встреч `YYMMDD | YYMM_CODIGO | EMPRESA | Tipo`, задачи-соглашения
  `[Categoria] — [описание]`) и комментирует, если формат не соблюдён —
  **сам никогда не переименовывает задачу**;
- следит, что описание (Notes) заполнено на испанском и русском (`[ES]\n---\n[RU]`),
  добавляет шаблон или недостающий перевод, не переписывая существующий текст;
- ищет возможные дубли — сразу при создании задачи и еженедельно (по
  воскресеньям) сводным отчётом по всем проектам — и только помечает их
  комментарием, **не закрывает и не удаляет** задачи;
- мягко напоминает, если не назначен исполнитель;
- никогда не меняет исполнителя без явной просьбы.

Все взаимодействия с людьми — только двуязычные (ES/RU) комментарии в самой
задаче Asana, как описано в разделе 6 инструкции.

## Архитектура

- **Node.js / TypeScript**, Express-сервер принимает вебхуки Asana в
  реальном времени (`POST /webhooks/asana`) + `node-cron` для еженедельного
  отчёта о дублях.
- **Asana REST API** (Personal Access Token) — чтение задач, добавление
  комментариев, обновление Notes.
- **Claude (Anthropic API)** — используется для «смысловых» проверок,
  которые не решаются регулярками: действительно ли слово — испанский
  глагол в инфинитиве, перевод ES↔RU, и итоговое подтверждение дублей
  (чтобы не путать «Factura electricidad Casa A» и «Factura electricidad
  Casa B» — разные объекты с похожими словами).

```
src/
  asana/        — клиент Asana REST API
  claude/       — клиент Anthropic API (переводы, инфинитив, оценка дублей)
  rules/        — правила из разделов 1, 3, 4 инструкции
  engine/       — дерево решений (раздел 5) и еженедельный скан дублей
  webhook/      — приём и верификация вебхуков Asana
  scripts/      — регистрация вебхуков
config/projectCodes.json — справочник кодов проектов (раздел 7)
```

## Настройка

### 1. Переменные окружения

```
cp .env.example .env
```

| Переменная | Назначение |
|---|---|
| `ASANA_ACCESS_TOKEN` | Personal Access Token — https://app.asana.com/0/my-apps |
| `ASANA_WEBHOOK_SECRET` | Заполняется автоматически после первого handshake (можно оставить пустым) |
| `ANTHROPIC_API_KEY` | Ключ Anthropic API |
| `ANTHROPIC_MODEL` | По умолчанию `claude-sonnet-5` |
| `PORT` | Порт HTTP-сервера (по умолчанию 3000) |
| `PUBLIC_BASE_URL` | Публичный HTTPS-адрес сервиса — нужен для вебхуков Asana |
| `REPORT_PROJECT_GID` | GID проекта (обычно PEX), куда публикуется сводный отчёт о дублях |
| `DUPLICATE_SCAN_CRON` | Расписание еженедельного скана (по умолчанию `0 9 * * 0` — воскресенье 09:00) |
| `DUPLICATE_SCAN_TZ` | Таймзона для расписания |

### 2. Справочник проектов

В `config/projectCodes.json` уже перенесена таблица из раздела 7. Нужно
вручную заполнить `asanaProjectGid` для каждого проекта — GID берётся из
ссылки на проект в Asana (число в конце URL). Без GID проект не
отслеживается. Этот файл нужно дополнять при появлении новых проектов
Gestión Operativa — как и написано в инструкции.

### 3. Запуск локально

```
npm install
npm run dev
```

Для получения вебхуков в реальном времени локальный сервер должен быть
доступен снаружи (например, через `ngrok http 3000`) — тогда
`PUBLIC_BASE_URL` указывает на туннель.

### 4. Регистрация вебхуков Asana

Сервис должен уже быть запущен и доступен по `PUBLIC_BASE_URL`:

```
npm run register-webhooks
```

Скрипт создаёт вебхук на каждый проект с заполненным `asanaProjectGid`.
Asana сразу присылает handshake-запрос — сервис сам сохраняет секрет в
`.webhook-secret` (в `.env` можно тоже зафиксировать `ASANA_WEBHOOK_SECRET`,
чтобы секрет пережил пересоздание контейнера).

### 5. Деплой в Docker

```
docker build -t asanchez .
docker run -p 3000:3000 --env-file .env asanchez
```

Убедитесь, что `.webhook-secret` персистентен (volume) либо
`ASANA_WEBHOOK_SECRET` задан в окружении — иначе после рестарта контейнера
подписи вебхуков перестанут проверяться и события будут отклоняться (401).

## Что агент никогда не делает без разрешения человека

- не переименовывает задачи самостоятельно;
- не закрывает задачи;
- не удаляет задачи (в т.ч. подозреваемые дубли);
- не меняет исполнителя без запроса.
